# Plan thoughts

- Humans are going to be the slow part in this workflow. There will be up to 12 humans working on a project at the same time (only half of those would be developers) They have limited time and attention and will need to work collaboratively. So we need to optimise the workflow, in order to make the most of the Humans in the loop and to organise and prioritise the issues that are worked on and deployed. The ability to collaborate is key to making this process work.
- We need clear, protected, deterministic and monitor-able handover gates between agents and stages of the workflow.
- We need to build and alter the workflow in a collective and phased approach. Starting with small vertical slices of the workflow to test capability and up-skill Humans. There will also be alterations in the workflow as we learn more about the flow itself and Human ways of working
- We need to think about how we best integrate with the existing workflow, including the creation and tracking on Jira tickets. We need methods to easily transfer the data from Jira tickets into (and possibly out of) GitHub Issues
- We need to determine what is the source-of-truth is with regards to Product Requirements and how they are reviewed and tracked
- I think best in pictures. So we need to create a reliable method of tracking the workflow itself and the project architecture using pictures. These pictures will be outputting what is happening within the repo but also we need a method to use created pictures as a form of input into the development of the workflow
- I need to learn and up-skill on GitHub Actions and GitHub Issues. We can draw this into the plan or I can learn whilst creating the workflow with guidance from you.

## Assumptions

- For now, assume 6 developers and no other humans in the loop.

## Deferred (later iteration)

- **Non-developer roles:** define gates for the other ~6 humans (e.g. requirements sign-off, plan approval, acceptance). Explore once the developer-only workflow is working.
